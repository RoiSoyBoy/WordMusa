# Retro — 2026-05-28 — Bug Fixes Post-Deployment

## What we built / fixed

- **Removed App Check entirely** — backend (`verifyAppCheck` removed from all 7 functions) and frontend (`initializeAppCheck` removed from `firebase.js`, `getAppCheckToken` removed from `SpotifyAuth.js`). Root cause of iOS Safari failure: App Check 24h reCAPTCHA throttle was blocking all Firestore operations on iOS.
- **Fixed LRCLIB CORS on iOS Safari** — `useLyricSync` now tries direct LRCLIB fetch first, falls back to backend `lyricsFetch` on failure. Chrome worked because songs were already in Firestore cache; Safari hit cache misses and LRCLIB blocked the cross-origin request with `TypeError: Load failed`.
- **Fixed Firebase Hosting deploying stale build** — `firebase.json` had `"public": "dist"` (relative to `backend/`) but exports go to `frontend/dist/`. Fixed by adding `fs.cpSync` to `inject-fonts.js` to sync `frontend/dist → backend/dist` after every build. All previous deploys this session were serving an old bundle.
- **Fixed `recordWordEncounter` never called** — destructured from `useWordTracking`, added `currentTrackRef` + `encounteredRef` to avoid stale closures and double-counting. Now fires for every psychometric word that passes through the active lyric line.
- **Permanent GOOGLE_APPLICATION_CREDENTIALS fix** — `deploy-functions.ps1` runs `gcloud run services update --remove-env-vars` on all Cloud Run services after every functions deploy. Wired to `npm run deploy:functions`.
- **Added Cache-Control: no-cache for index.html** in `firebase.json` to prevent Safari caching stale HTML.

## What broke and why

- **Multiple wasted deploys** — Firebase was deploying `backend/dist/` (old copy) while all changes went to `frontend/dist/`. Took several rounds of debugging to identify the root cause.
- **Eruda debug tool never visible** — injected into the wrong dist folder for the same reason; user could never find the floating button.
- **PowerShell em dash encoding** — `deploy-functions.ps1` used `—` (em dash) characters; Windows PowerShell 5.1 read the UTF-8 bytes as CP1252 and mangled them into stray `"` characters, breaking the parser.

## Decisions made

- App Check removed permanently from both frontend and backend — not needed given Spotify dev mode wall (25 users) + `verifyAuth` + rate limiting.
- LRCLIB backend fallback is always available but only triggered on failure — keeps the fast direct path for platforms that support it.
- `inject-fonts.js` now owns the `frontend/dist → backend/dist` sync step so the build pipeline is self-contained.
